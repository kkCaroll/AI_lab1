### 2.2 P4.2 置信区间与配对检验

统计口径如下，均不依赖 scipy。

| 项目 | 方法 | 理由 |
| --- | --- | --- |
| 单方法准确率的区间 | Wilson 得分区间，95% | 小样本与接近 0 或 1 的比例下优于正态近似，补充表原按正态近似算出的 Base 行一并改用 Wilson 并注明 |
| 方法间差异 | 同一批样本的 McNemar 精确检验，双侧 | 配对设计下只比较两法判断不一致的样本，检验功效高于两独立比例检验 |
| 差值区间 | 配对比例差的标准误 sqrt((b+c)−(b−c)^2/n)/n，按正态近似给 95% 区间 | 与 McNemar 的 b、c 计数同源，可直接由 2×2 表算出 |
| 效应量 | 报告 b 与 c 的条数及 McNemar 比值比 b/c | 比值比在 c 为零时加 0.5 修正，并注明修正 |
| 多重比较 | 按预设家族分别做 Holm 校正 | 家族一为四种方法各与基线的比较，每数据集 4 项；家族二为四种微调方法两两比较，每数据集 6 项；两数据集分开校正 |
| 行为指标 | 截断率与抽取失败率给 Wilson 区间，不单独做显著性检验 | 这两项用于描述输出退化，不作方法优劣的推断 |

对 GSM8K 与 ARC 分别计算。行为指标按数据集分别报告，GSM8K 侧另报生成均长与截断率，用于支撑训练目标窄化的判断。ARC 一律使用 v3 逐条文件，v2 只作稳健性对照，其读数已回算，不进入配对检验的主表，避免同一批样本上两套口径混用。

脚本输出两份产物。`exp1/runs/analysis/summary.json` 存全部数值，供 P5.2 生成表格与图。`RECORD/03-统计分析与配对检验.md` 存人可读的表格与结论摘要，并注明脚本版本与运行命令。

单元测试 `exp1/tests/test_analyze.py` 覆盖三处易错逻辑，即 Wilson 区间在 p 为 0 与 1 时的取值、McNemar 精确检验在手造 2×2 表上的 p 值、Holm 校正的单调性。测试不加载模型，毫秒级完成。

### 2.3 P4.3 四个分析问题

四个问题的回答以 P4.2 的数值为准，先写要点，再改写为报告正文。要点草稿存 `RECORD/04-四个分析问题的回答.md`，每条注明所依据的表格或运行标识。

问题一，微调是否提高 GSM8K 准确率。主表的点估计均为下降，M4 低 42 条即 3.18 个百分点，M1 低 118 条，M2 低 209 条，M3 低 289 条。配对检验显示四项降幅在 Holm 校正后均显著，M4 与基线的 p 为 0.0166，M1 至 M3 的 p 均小于 0.0001。结论写为四种方法均未提高 GSM8K 准确率，自研方法的降幅最小但仍显著低于基线。

问题二，不同方法的差异。核心对比是 M4 与 M2，两者共享 LoRA 底座，唯一差异是 KL 项。GSM8K 上 M4 高 167 条即 12.66 个百分点，Holm p 小于 0.0001；ARC 上 M2 高 22 条即 1.88 个百分点，Holm p 为 0.3357，不显著。M4 与 M1、M3 的 GSM8K 差值分别为 5.76 与 18.73 个百分点，Holm p 分别为 0.0003 与小于 0.0001。ARC 上 M4 与 M1 的差值为 1.02 个百分点，p 为 0.5675；与 M3 的差值为 5.55 个百分点，p 为 0.0032。方法排序与可训练参数占比、优化难度、正则强度一并讨论，不把单一读数直接归因于方法类别。

问题三，ARC 是否下降。答案依赖抽取口径，不能由单一准确率断言。v3 下 M3 低于基线 25 条，M1、M2、M4 分别高 28、62、40 条。按配对检验，LoRA 与 M4 相对基线显著为正，Holm p 分别为 0.0012 与 0.0218；Full SFT 的 2.39 个百分点与 P-Tuning v2 的负 2.13 个百分点均不显著。v2 下 M2 与 M3 分别低 66 与 164 条，M1 与 M4 分别高 10 与 36 条。M2 的排序在两套口径间翻转，原因是其冗长输出被 v3 的全文正文查找接住，而 v2 记为抽取失败。故报告的主结论取 v3，同时并列 v2、截断率与抽取失败率。行为层面四种微调方法均出现退化，ARC 生成均长由基线的 12.7 token 增至 Full SFT 的 279.7、LoRA 的 174.4、P-Tuning v2 的 26.3 与 M4 的 23.6，截断率依次为 0.4514、0.2696、0.0034 与 0.0000，抽取失败率依次为 0.0768、0.0333、0.0904 与 0.0026。M4 的输出行为最接近基线。由此把遗忘的判据从准确率单指标改为准确率与输出行为的联合判据。

问题四，遗忘的成因与缓解。候选成因分四条，参数漂移使基座分布被目标分布覆盖，训练目标只含 GSM8K 的短答案与去标注推理，输出长度分布随之收缩，选择题的格式遵循能力随指令微调一起退化，基座在 GSM8K 测试集上可能已有污染而使可提升空间被压缩。GSM8K 生成均长由基线的 208.4 token 降至 Full SFT 的 93.5、LoRA 的 108.7 与 P-Tuning v2 的 110.0，M4 为 185.9，与输出长度收缩一条直接对应。每条给出对应证据，前三条用生成长度、截断率、抽取失败率与 M4 的 β 扫描，第四条用 R9 的局限说明。缓解方面，KL 项把输出分布拉回基座，M4 在 GSM8K 上高于 M2 167 条，ARC 截断归零，但 ARC 准确率低于 M2 22 条且该差值不显著，说明它缓解的是行为退化与目标域退化，并不保证通用准确率同步上升。β 扫描的五档读数呈单调权衡，系数越大越接近基座，目标域收益越小，1.6 是按预登记规则取的档，不是经验最优点。

局限单列一段，至少含单种子、单次评测、抽取规则敏感性、基座污染、硬件由 V100 换为 A10 五项。单种子不补做，理由是重训四种方法的成本超出本阶段预算，报告中明确写为局限。

### 2.4 通用文本困惑度的取舍

R11 预设以通用文本困惑度作为遗忘的辅助指标。现有补充表该列为空，需在以下三案中择一。

| 方案 | 做法 | 成本 | 证据强度 |
| --- | --- | --- | --- |
| 甲 | 取 WikiText-2 或 C4 的固定抽样约二百万 token，上传 OSS，新增 `scripts/measure_ppl.py`，五个模型各算一次滑动窗口困惑度 | 一次 DLC 任务，约二十分钟，另需一次数据上传 | 最高，直接测通用语言建模能力 |
| 乙 | 以 ARC 题干与选项文本算困惑度，不新增语料 | 一次 DLC 任务，约十分钟 | 中等，语料属通用科学文本但与评测集同源 |
| 丙 | 删去该列，在局限中说明以 ARC 行为指标替代 | 无 | 最低，R11 的验证方式须改写 |

已定取甲，语料取 WikiText-2，抽样二百万 token，五个模型共用同一份 token 流。语料以文本文件上传 OSS 的 `exp1/data/raw/`，容器内不再联网下载。WikiText-2 的 train 划分共 2,517,233 个 Qwen token，取前二百万，回编码后仍为 2,000,000，字符 8,673,272，文件 8.4 MiB，SHA256 为 `1844527ff755f280d1e5e56f6d54fa590bd6343b72d45f5e626d97091fa5c4c5`。该划分属训练集，绝对困惑度会因预训练重叠而偏低，故报告只解释五个模型之间的相对差异，不把绝对值与文献对照。

抽样脚本为 `exp1/scripts/make_ppl_corpus.py`，从 parquet 的 text 列读取全文，用 Qwen 分词器编码后取前二百万 token，再解码写回文本。本地已执行并核对回编码数恰为二百万。测量脚本为 `exp1/scripts/measure_ppl.py`，按不重叠的 1024 token 窗口切分，窗口内第 2 位至末位计分，首位不计，损失按 float32 分块求和后除以计分 token 数并取指数。一次任务的串联脚本为 `exp1/scripts/run_ppl.sh`，五个模型各起一个进程，任一项失败不中断其余项。

DLC 任务命令如下，`METHODS` 缺省为五项全测。

```bash
OUTPUT_ROOT=/mnt/data/exp1/runs/P4-ppl bash /mnt/code/AI_lab1/exp1/scripts/run_ppl.sh
```

五项权重的位置为，M0 取基座目录，M1 取 `runs/P2-6/M1/train/epoch-3` 的完整检查点，M2 取 `runs/P2-6c/M2/train/epoch-3` 的适配器，M3 取 `runs/P2-6c/M3/train/epoch-3` 的适配器，M4 取 `runs/P3-1/kl1.6/train/epoch-3` 的适配器。M1 与 M3 两项目前只有目录命名规则可依，提交前须在 OSS 控制台核对实际前缀，脚本已把四项留作环境变量覆盖。

读数的事先解释规则如下。若微调模型的困惑度高于基座，将其读作通用语言建模能力退化的证据，与 ARC 行为指标同向。若低于基座，则说明 GSM8K 微调没有损害 WikiText-2 上的语言建模，遗忘是任务与格式层面的现象，而不是通用分布的全面退化。两种结果都按实报告，不因与预期不符而删去该指标。

困惑度只测原始文本续写，不测指令遵循与推理，且基座本身是指令模型，故该指标不能单独代表通用能力。报告中它与 ARC 准确率、截断率、抽取失败率并列，四项同向时才作强结论，不同向时按维度分别陈述。

运行时间按五个模型各前向二百万 token 估算，合计一千万 token。锚点取 R2-13 全参微调的训练吞吐 2311 token/s，该值含反向传播，纯前向约为其三倍，即约七千 token/s。一千万 token 约需一千零五十至一千四百五十秒。加容器启动与依赖安装约五十秒、语料分词约十五秒、五次模型加载约四十秒、汇总写盘约十秒，合计约十九至二十六分钟，按二十至三十分钟报。计费按每分钟 0.1748 元计约四至五元，最长运行时长按两倍估时填一小时。上述估算以不重叠的一千零二十四 token 窗口为准，若改用常见的五百一十二步长与一千零二十四窗口，前向 token 数翻倍，时间增至三十五至五十分钟，故首版取不重叠窗口并在方法中注明。

统计上二百万 token 已远超所需。困惑度是 token 级负对数似然的均值，标准误随样本数开方缩小，WikiText-2 的 test 与 validation 合计约四十六万 token 已足以把均值的标准误压到千分之几，运行时间约五至七分钟。若只想得到稳定的相对排序，四十六万 token 一档更划算；二百万一档的收益主要是让模型间的小差异也落在噪声之外。

### 3.4 P5.4 验收复现

课程验收含三项操作，即用基座模型跑一道 GSM8K 测试题、运行评测程序、展示某种方法的训练配置与结果。本机已有基座权重与 CPU 推理通路，验收可按下列顺序预演。

| 操作 | 命令要点 | 预期 | 时限 |
| --- | --- | --- | --- |
| 单题生成 | `python -m src.eval --model-path models/Qwen3-0.6B --dataset gsm8k --split test --limit 1 --dtype float32 --device cpu --output-dir runs/acceptance/gsm8k-1` | 打印题目、输出、抽取结果与判对 | 三分钟内 |
