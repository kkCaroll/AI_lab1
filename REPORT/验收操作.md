2026-10-22 拟并实测，2026-11-11 增补第五项。全部操作在本机 CPU 上完成，不联网，不提交 DLC 任务。实测所用机器为开发本机，数字供现场估算时间之用。

## 一 准备

工作目录为 `exp1`。虚拟环境位于仓库根目录，若命令行前未出现 `(.venv)`，先激活，或把命令中的 `python` 换成 `..\.venv\Scripts\python.exe`。

```powershell
cd C:\DATA\大三上课程\人工智能\实验一\exp1
..\.venv\Scripts\Activate.ps1
```

五类文件就位。基座权重在 `models/Qwen3-0.6B`，数据在 `../data/raw`，适配器在 `models/adapters/M4`，全参微调检查点在 `models/M1`，前缀适配器在 `models/adapters/M3`。

命令一律写成一行。PowerShell 不认反斜杠续行，写成多行时须用反引号，且反引号后不能有空格。

输出目录必须是不存在的新目录。评测入口检测到旧目录会拒绝运行，避免续写造成产物混杂。

此处有一处已知限制。该条答对时样例段只打印一句无抽取失败，屏幕上不出现题干与模型原文。需要现场展示原文时，补一条读取产物的命令。

若老师指定题目编号而非第一条，目前入口只支持 `--limit`，取前若干条。临时办法是把 `--limit` 调到该题编号加一，再从产物里读该条。后续可给入口加 `--index` 参数，见第六节。

## 四 操作三 展示训练方法的配置、日志与结果

按三层讲，每层约一分钟。以自研方法为例，其余方法同构。

第一层看配置。打开 `exp1/configs/custom.yaml`，指出 rank 8、alpha 16、dropout 0.05、目标模块 q、k、v、o 四个投影、正则系数 1.6。再打开 `RECORD/01-实验配置.md` 第一节，指出学习率 1.0e-4、轮数 3、微批 8、累积 8、有效批 64、最大长度 512、精度 float16、训练时长 40.5 分、显存峰值 15.17 GiB。

这里有一处必须提前知道的差异。`configs/full_sft.yaml`、`configs/lora.yaml` 与 `configs/ptuning.yaml` 中的学习率是文件默认值，分别为 1.0e-4、2.0e-4 与 3.0e-4，与正式运行的 2.5e-5、1.0e-4 与 1.2e-2 不同。正式运行以命令行覆盖，覆盖记录写在各任务日志的配置行。老师若对照文件与记录，先说这一句，再打开日志的覆盖行。

第二层看日志。打开 `运行输出日志/P3/ai-lab1-R3-4-kl1.6_成功.txt`，指出四行。配置行含 `train.lr` 与 `custom.kl_weight` 的覆盖值；参数量行为总量 598,343,680 与可训练 2,293,760；每轮末行的平均损失依次为 1.0228、0.9418、0.9285；末尾汇总行为总步数 333、用时 40.5 分、显存峰值 15.17 GiB、处理 token 3,962,898。日志中还有一行正则项读数，每 token 散度 0.0841，系数 1.6，可用来说明 KL 项确实参与计算。

第三层看结果。打开 `RECORD/00-结果表.md` 主表，指出自研方法 GSM8K 0.5701 与 ARC 0.5546。再指出它与 LoRA 的差别只有 KL 一项，GSM8K 高 12.66 个百分点，p 小于 0.0001，所以这一差值可以归给 KL 项。

若老师想看权重，打开 `exp1/models/adapters/M4/`，两个文件为配置与权重，参数 2,293,760，224 个张量。该目录不入仓库，本机保留。

## 六 操作五 全参与前缀两种保存形式的载入

前四项演示基座与自研方法的适配器。老师若要核对全参与前缀两种方法的保存与载入，再跑两条，命令只差 `--model-path` 与 `--adapter`。

```powershell
python -m src.eval --model-path models/M1 --data-dir ../data/raw --dataset gsm8k --split test --limit 1 --device cpu --dtype float32 --output-dir runs/acceptance/m1-1
python -m src.eval --model-path models/Qwen3-0.6B --adapter models/adapters/M3 --data-dir ../data/raw --dataset gsm8k --split test --limit 1 --device cpu --dtype float32 --output-dir runs/acceptance/m3-1
```

| --- | --- | --- |
| 目录体积 | 2.2 GiB，六个文件 | 4.4 MiB，三个文件 |
| 载入方式 | `--model-path` 直接指向检查点目录 | `--adapter` 与基座组合 |
| 权重加载 | 4.0 秒 | 6.1 秒 |

| 抽取规则 | marker | marker |

体积相差约五百倍，与可训练量 596,049,920 对 1,146,880 同序，这一对照说明保存的确分为全量与增量两种形式。

载入路径的差别须讲清。M1 目录自带 `config.json` 与分词器文件，可直接作 `--model-path`，无须基座参与。M3 目录只有 `adapter_config.json` 与权重两个文件，配置里记着基座名，单给适配器目录无法运行，必须先载基座再挂适配器。

M1 这一条答错，标准答案 18，抽取值 72。输出为 `36 eggs * $2/egg = $72` 后接 `#### 72`，推理连贯，错在把题目读成先吃掉 12 个蛋，属模型自身理解错误而非加载异常。同一题基座答对，两条并放即全参微调后基础算术退化的现场例证。

## 八 排错与回退

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| `unrecognized arguments: \` | PowerShell 不认反斜杠续行 | 改为一行，或用反引号续行 |
| 输出目录已存在 | 入口拒绝复用旧目录 | 换一个新目录名 |
| CPU 上报算子不支持 | float32 未指定，默认取了半精度 | 显式加 `--dtype float32` |
| 模型路径报错 | 未在 `exp1` 下运行 | 先 `cd` 到 `exp1` |
| 适配器目录单独加载报错 | 只给 `--adapter` 而 `--model-path` 指向适配器目录 | 基座作 `--model-path`，适配器目录作 `--adapter` |
| 找不到 `python` | 虚拟环境未激活 | 用 `..\.venv\Scripts\python.exe` |
| 显存不足 | 仅出现在 GPU 路径 | 入口会自动折半重试，或改 CPU |

全程不依赖 GPU 与网络，任何一步失败都可以换新目录重跑，不污染已有产物。

## 九 两处必答细节

第一，为什么 CPU 上必须 float32。本机无法用 GPU，CPU 上缺半精度矩阵乘的实现，指定 float16 会在生成时报算子不支持。float32 只改变数值路径，不改变贪心解码的判定逻辑，读数与正式运行同序，但不逐条相同。

第二，抽取失败如何计入准确率。失败按答错计，不从分母中剔除。理由是否则准确率会随模型越不守格式而虚高。失败样例会单独落盘到 `extract_failures_*.jsonl`，报告中的抽取失败率就是这部分样本的占比。

## 十 待补事项

操作一在答对时不打印题干与原文，建议给评测入口加一个只打印不落盘的展示开关。指定题目编号目前只能靠 `--limit` 间接实现，建议加 `--index`。两项都属展示层改动，不改判定逻辑，改后需重跑一次本手册第二至六节并更新实测耗时。

验收前用新目录完整预演一次，确认磁盘缓存已就位，首次运行会比上表慢十余秒。
