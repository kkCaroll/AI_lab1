# 五 实验总结

## 5.1 完成的工作

本实验在 Qwen3-0.6B 上完成了五种方法的训练与评测，包括基座、全参数监督微调、LoRA、P-Tuning v2 与一种自研的 KL 正则化 LoRA，并在 GSM8K 与 ARC-Challenge 两个测试集上给出完整读数。

围绕这个主线还做了四件事。第一，搭了一套数据与评测管线，训练与评测共用同一个 prompt 模板，答案抽取独立成模块并有单元测试，逐条预测全部落盘。第二，从 GSM8K 训练集划出 400 条开发集，用它选学习率、轮数与正则系数，测试集只在超参确定后使用。第三，完成统计分析与配对检验，给出 Wilson 区间、McNemar 精确检验与 Holm 校正。第四，补测通用文本困惑度，用 WikiText-2 前二百万 token 观察语言建模层面的变化。

## 5.2 主要发现

第一，微调没有提高 GSM8K 准确率。四种方法全部显著低于基座，降幅从 3.18 到 21.91 个百分点不等。基座本身在这个测试集上偏高，训练目标又只保留了简短的答案正文，两者共同压缩了微调的收益。

第二，KL 正则有效，但只解决一部分问题。它在 GSM8K 上比 LoRA 高 12.66 个百分点，把输出长度与 ARC 的格式退化基本拉回基座水平，但没有把 GSM8K 拉回基座，ARC 准确率也没有超过 LoRA。

第三，遗忘是多维的。按准确率看，ARC 没有统一下降；按输出行为看，四种方法都退化；按困惑度看，LoRA 与自研方法没有损害通用语言建模，P-Tuning v2 的前缀则与无模板文本严重失配。任何单一指标都不足以描述遗忘。

第四，ARC 的读数对抽取口径敏感。LoRA 与 P-Tuning v2 在 v2 与 v3 两套口径下符号相反，前者靠冗长输出被新增规则接住，后者靠短句作答。自研方法对口径几乎不敏感。

## 5.3 可改进之处

1. 补多种子实验。四种方法各只训练一次，方法间差异没有包含训练随机性，重复三次以上会更稳。
2. 补容量对照。LoRA 与 Full SFT 的差距可能来自低秩容量，固定 rank 扫不同 rank 即可分离。
3. 补数据混合或回放。把少量通用语料混进训练，是文献里常用的缓解手段，本实验没有做。
4. 改进评测。ARC 的作答格式退化很严重，可以另设一个只判格式的指标，把格式退化与知识遗忘分开。
5. 改进困惑度协议。P-Tuning v2 的读数受模板影响，若用带模板的语料再测一次，可以得到更有可比性的数值。

## 5.4 个人体会

（此处由本人撰写。可从下面几个问题入手。）

1. 哪个读数最出乎意料。例如基座在 GSM8K 上比所有微调模型都高。
2. 哪个环节最费时间，为什么。例如显存不足导致的微批调整，或抽取规则的迭代。
3. 对训练与评测必须匹配的理解。prompt 模板、生成上限、抽取规则三处，任何一处不一致都会让读数失去可比性。
4. 如果重做会改什么。例如先做小样本对照，或先补污染检测。
5. 对参数高效微调的认识。可训练参数少不等于遗忘少，P-Tuning v2 就是例子。
